# Changelog

## 0.1.2 (2026-10-23)

- New: `patientFetch(url, init?, { tries = 6, delayMs = 300, maxDelayMs = 4000, onRetry?, retryOn? })`, the one rule for
  asking an ERDDAP request again when the server drops it (the places page and the indicators viewer each carried a copy).
  Retried: a network error, a 404 whose body says "Currently unknown datasetID" (the mirror answers the same url 404 and
  200 by turns), a 429 and a 5xx, after a pause of `delayMs` x the try, capped at `maxDelayMs`. Any other answer, a 4xx
  included, is returned at once. `init.signal` aborts it at once, between tries too; `onRetry` reports each retry (try,
  pause, reason, status). After `tries` failed tries it throws a `PatientFetchError` (an `ErddapUnreachable`, so the message
  names the host and the last status: "erddap.oceanmetrics.io did not answer (HTTP 503 Service Unavailable, 6 tries)"),
  with `status` and `cause`. Also exported: `isRetryable` (the default rule, for a `retryOn` that adds to it), `UNKNOWN_DATASET`.
  `fetchRetry` is unchanged. To get a `typeof fetch` for `lobeAxes`, `fetchTimeExtent` and `sliceSource`:
  `(u, init) => patientFetch(u as string, init)`.
- Differs from the two app copies on purpose: they returned the last response after the last try; this throws, and only a
  404 that names the unknown dataset is retried (they retried every 404).

## 0.1.1 (2026-10-23)

- Fix: `sliceSource().slice()` read the lobes' slabs without the `SELECT DISTINCT` that `runPreview` applies, so where two
  places' boxes overlap (Channel Islands and Chumash) every cell of the overlap came back twice. Regression test with two
  overlapping synthetic slabs.

## 0.1.0 (2026-10-23)

The browser engine, build week 2 step 2b: erddap-places' engine as a platform package, so the indicators Map's `grid`
slot and the live preview run the same SQL as the Python engine (`om_extract`).

- **Moved from erddap-places** (app 0.3.12): `gridMask` as `mask.ts` and `wkb.ts` byte for byte; `placeLobes` (now
  `lobes.ts`, reading a `LobePlace`); `erddap.ts` (`griddapUrl`, `griddapSliceUrl`, `tabledapUrl`, `pickFormat`,
  `fetchAxis`, `fetchSlab`, the constraint rules), `extent.ts`, `fetchRetry.ts` and `cells.ts` unchanged but for `.js`
  specifiers; `catalog.ts`'s pure functions as `dataset.ts` (`toDataset`, `valueExpr`, `statsTemplate`, `lobeLonSpan`,
  `resolveDataset` ...); the precompute's `window`, `chunks` and `chunkDaysFor` as `chunks.ts`, the two limits now options.
- **The SQL templates** in `sql/` (`stats_daily`, `stats_categorical`, `last_step`, `stats_tabledap`,
  `points_tabledap`), shipped as strings (`TEMPLATES`, generated by `scripts/sql-templates.mjs`), rendered by `render`.
- **`Engine`** over DuckDB-WASM (a peer, >= 1.29): `registerBuffer`, `insertMask` (Arrow IPC), `insertRows`, `exec`,
  `runTemplate`, `toParquet`, `dropFile`; the app passes `connect()`, and `connectBrowser(duckdb, bundles)` is the
  browser boot. `toRows` scales DECIMAL columns (DuckDB-WASM returns them unscaled).
- **The live preview**: `previewWindow`, `lobeAxes`, `lobeMasks`, `runPreview` (a chain of chunked griddap Parquet
  requests, `onChunk` in time order, abortable) and `sliceSource` (a `SliceSource` for `@oceanmetrics/map`'s `gridSlot`).
- Dependencies: turf 7.4.0 pinned (the parity fixtures record it); `@duckdb/duckdb-wasm` and `apache-arrow` as peers.
- Size budget set from a measurement: 26 794 B gzip, budget 40 000 B.
